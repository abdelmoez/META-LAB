I want you to improve the **Manuscript Editor’s handling of fields that require manual user input**.

Throughout the manuscript, some content may appear inside square brackets, for example:

`[Enter institution name]`
`[Add interpretation here]`
`[Specify subgroup]`

Treat anything enclosed in `[...]` as a **manual-input placeholder** that requires the user's attention.

### Required behavior

1. **Automatically detect manual-input placeholders**

   * Detect all editable placeholders enclosed in square brackets throughout the manuscript.
   * These should be treated differently from normal manuscript text.
   * The system should maintain awareness of how many unresolved placeholders remain.

2. **Easy navigation between placeholders**

   * Give users a fast and intuitive way to move between unresolved placeholders.
   * Ideally provide:

     * **Previous placeholder**
     * **Next placeholder**
   * Keyboard shortcuts should also be supported where appropriate.
   * Navigation should automatically scroll the relevant placeholder into view and focus it.
   * It should work across the entire manuscript, even if placeholders exist in different sections.

3. **Select the entire placeholder on click**

   * When the user clicks anywhere inside a placeholder, automatically select the **entire placeholder, including both square brackets**.
   * Example:

     * Clicking anywhere inside `[Enter institution name]`
     * should select the entire `[Enter institution name]`
   * This allows the user to immediately type and replace the placeholder without manually highlighting it.

4. **Make unresolved placeholders visually recognizable**

   * They should be noticeable enough that users understand they require manual input, but they should not make the manuscript visually distracting.
   * Use subtle styling consistent with the existing Manuscript Editor design.
   * Hovering over one could show something simple such as:

     * **“Manual input required”**

5. **Prevent placeholders from being accidentally missed**

   * Show a subtle unresolved-placeholder counter somewhere appropriate in the editor, for example:

     * `3 manual fields remaining`
   * Clicking the counter could navigate to the next unresolved field or open a small list of remaining placeholders.
   * The user should be able to see which manuscript section contains each unresolved field.

6. **Automatically mark placeholders as resolved**

   * Once the user replaces the placeholder with actual text and the square-bracket placeholder no longer exists, remove it from the unresolved list automatically.
   * The count and navigation state should update immediately without requiring refresh or manual synchronization.

7. **Do not interfere with legitimate square brackets**

   * Be intelligent about detecting placeholders.
   * Square brackets that are legitimately part of scientific writing, references, formulas, statistical notation, quotations, or imported content should not automatically become manual fields unless they actually represent a generated/manual-input placeholder.
   * If necessary, introduce an internal placeholder metadata/type instead of relying exclusively on parsing `[` and `]`.

8. **Integrate this with manuscript generation**

   * Whenever PecanRev generates manuscript text and there is information it genuinely cannot determine from project data, it may create a clearly defined manual placeholder.
   * Those placeholders should automatically enter this navigation system.
   * Do not create placeholders for information that can already be obtained from the project, search history, screening, extraction, analysis, project metadata, or other available data. The system should populate those automatically whenever possible.

9. **Preserve normal editing behavior**

   * Undo/redo must continue working normally.
   * Copy/paste should work correctly.
   * Autosave must continue working.
   * Placeholder navigation should not break text selection, comments, citations, formatting, tables, or other editor functionality.

### UX goal

The purpose of this feature is to make manual manuscript completion almost impossible to overlook.

A user should be able to open the Manuscript Editor, immediately know whether anything still requires their input, and move through every required field sequentially without searching through the manuscript manually.

The experience should feel similar to moving through fields in a professionally designed form, while still preserving the flexibility of a full manuscript editor.

Please inspect the existing Manuscript Editor architecture first and implement this in the cleanest way possible rather than adding a fragile workaround. Reuse the existing design system, autosave, manuscript synchronization, history/versioning, and editor architecture wherever appropriate.
