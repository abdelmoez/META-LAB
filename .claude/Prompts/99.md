# Pecan Search Engine — Dynamic Concept Interaction Redesign

I want you to redesign and improve the **concept cards/groups within the “Select and Build Key Terms” page** of the Pecan Search Engine.

This should be treated as a meaningful UX refinement, not a superficial animation task. First inspect the existing implementation, understand how concepts are selected and edited, and then implement the most intuitive and polished interaction possible.

Use as many specialized agents as helpful for UX analysis, frontend implementation, accessibility review, testing, and final quality control. Take the time necessary to produce a complete, production-ready result.

## Primary Goal

Make each concept visually interactive and easier to understand by allowing it to **dynamically expand and collapse** with subtle, smooth motion.

Users should immediately understand that:

* Each concept is clickable.
* Clicking a concept expands it.
* The expanded concept is the current active concept.
* Clicking elsewhere collapses it again.
* The interaction is smooth, calm, and visually comfortable.

## Required Behavior

### 1. Click to Expand

When the user clicks a concept:

* The selected concept should smoothly expand.
* Its width, height, internal spacing, or content area may increase as appropriate.
* The expansion should make the concept easier to inspect and work with.
* The concept should feel active and focused without appearing excessively large.
* Other concepts may shrink slightly, become more compact, or reduce their visual emphasis.

Only one concept should normally be expanded at a time unless the existing workflow clearly requires otherwise.

### 2. Click Outside to Collapse

When a concept is expanded and the user clicks anywhere outside that concept:

* The expanded concept should smoothly return to its default compact size.
* The page should return to its normal balanced layout.
* Clicking page controls, navigation, buttons, or another concept should behave naturally.
* Do not interfere with text fields, dropdowns, drag-and-drop behavior, term selection, or any existing workflow.

If the user clicks another concept, the currently expanded concept should collapse while the newly selected concept expands.

### 3. Make Clickability Obvious

It must be immediately apparent that concepts can be clicked to expand.

Use thoughtful visual cues such as:

* A subtle hover elevation or border change.
* A small expand/collapse chevron.
* A brief helper label such as “Click to expand” when appropriate.
* A pointer cursor.
* A lightweight hover preview.
* Clear focus styling.
* A slight size or background transition.

Do not rely only on hidden behavior that users must discover accidentally.

Avoid adding excessive instructional text. Communicate the interaction primarily through the design itself.

### 4. Motion and Animation Quality

The motion must be subtle, premium, and easy on the eyes.

Requirements:

* Use smooth easing rather than abrupt resizing.
* Avoid bouncing, exaggerated scaling, flashing, or distracting movement.
* Prevent layout jumping and content shifting unpredictably.
* Keep transitions fast enough to feel responsive but slow enough to understand.
* Animate only properties that perform well.
* Maintain a stable page structure during expansion and collapse.
* Respect the user’s `prefers-reduced-motion` system setting.

Choose the exact timing and easing based on professional UI standards and the existing PecanRev design system.

### 5. Expanded Concept Design

When expanded, the concept should provide a clearer workspace for the user.

Depending on the current implementation, the expanded state may show:

* The concept title more prominently.
* Selected keywords.
* Synonyms.
* MeSH terms.
* Free-text terms.
* Editing controls.
* AND/OR relationships.
* Add-term actions.
* Concept status or validation indicators.

Do not introduce unnecessary information. Preserve the current workflow and functionality while making the active concept easier to understand and edit.

### 6. Collapsed Concept Design

The collapsed state should remain useful and informative.

It should show enough information for the user to identify the concept, such as:

* Concept name.
* Number of included terms.
* Whether MeSH terms are present.
* A concise preview of selected terms.
* Expand indicator.

Do not make collapsed concepts so small that their meaning becomes unclear.

### 7. Responsive Layout

The behavior must work correctly across:

* Large desktop displays.
* Standard laptop displays.
* Tablets.
* Narrow browser windows.
* Mobile layouts if this page supports mobile use.

On smaller screens, expansion may happen vertically rather than horizontally if that produces a better experience.

Do not allow:

* Horizontal overflow.
* Overlapping cards.
* Cut-off text.
* Hidden controls.
* Broken grids.
* Unstable scrolling.

### 8. Keyboard and Accessibility Support

The interaction must not depend exclusively on the mouse.

Implement:

* Keyboard focus for every expandable concept.
* Expansion using Enter or Space.
* Collapse using Escape where appropriate.
* Clear visible focus indicators.
* Correct button or disclosure semantics.
* Accurate `aria-expanded` and `aria-controls` attributes where applicable.
* Screen-reader labels describing whether the concept is expanded or collapsed.
* Sufficient color contrast.

Clicking outside should not unexpectedly steal focus from a user who is typing or using keyboard navigation.

### 9. Preserve Existing Functionality

Do not break or remove any existing Search Engine functionality.

Specifically verify compatibility with:

* Selecting terms from the research question.
* Dragging or reordering terms.
* Adding keywords.
* Adding synonyms.
* Adding MeSH or controlled-vocabulary terms.
* Editing and deleting terms.
* AND/OR relationships.
* Beginner mode.
* Manual and automated search modes.
* Live query compilation.
* Per-database search strategies.
* Autosave.
* Project persistence.
* Search validation.
* Any progress or completion tracking.

The animation layer must enhance the workflow rather than interfere with it.

## UX Decision-Making

Do not blindly implement a basic CSS scale animation.

First examine:

* The current concept component structure.
* Existing state management.
* Page density.
* Grid or flex layout behavior.
* Beginner-mode behavior.
* Current hover and selection styling.
* How users add and manage terms.
* How the page behaves when many concepts exist.

Then choose the best expansion pattern for the actual interface.

Possible patterns include:

* Expanding the active concept within the grid.
* Giving the active concept more grid columns.
* Expanding vertically while other concepts remain compact.
* Using an active editing panel connected to the selected concept.
* Combining subtle card expansion with clearer active-state styling.

You are authorized to make the final UX decision based on the existing implementation. Choose the solution that is clearest, least disruptive, and most scalable.

## State Management Requirements

Create a clear, maintainable concept interaction state, such as:

* `activeConceptId`
* `expandedConceptId`
* Explicit collapsed and expanded states

Ensure that:

* Only the intended concept expands.
* Selecting another concept switches states cleanly.
* Clicking outside collapses the active concept.
* Escape collapses it.
* The concept does not collapse while interacting with controls inside it.
* Expansion state does not corrupt saved research data.
* Reload behavior is intentional.
* Expansion state is treated as UI state unless there is a strong reason to persist it.

Use a reliable outside-click mechanism and clean up all event listeners correctly.

## Performance Requirements

The page must remain smooth even with many concepts and terms.

Avoid:

* Re-rendering the entire Search Engine unnecessarily.
* Expensive layout calculations on every mouse event.
* Repeated global event listeners.
* Animating properties that cause severe layout thrashing.
* Unnecessary persistence requests.
* Animation libraries that significantly increase bundle size without justification.

Use the project’s existing animation solution if one is already installed and appropriate. Otherwise, prefer a lightweight implementation.

## Testing Requirements

Add or update tests covering:

1. Clicking a collapsed concept expands it.
2. Clicking the same concept again behaves intentionally.
3. Clicking another concept transfers the expanded state.
4. Clicking outside collapses the active concept.
5. Clicking controls inside the concept does not collapse it.
6. Pressing Enter or Space expands a focused concept.
7. Pressing Escape collapses it.
8. Reduced-motion settings disable or minimize animation.
9. Existing term selection and editing remain functional.
10. The design works with one concept.
11. The design works with many concepts.
12. The design works with very long concept names and terms.
13. Beginner mode remains correct.
14. Autosave and query compilation remain correct.
15. Responsive layouts do not overflow or break.

Perform manual testing at multiple viewport sizes.

## Acceptance Criteria

This task is complete only when:

* Concepts clearly appear clickable.
* Clicking a concept smoothly expands it.
* Other concepts become visually secondary without becoming unusable.
* Clicking outside smoothly collapses the expanded concept.
* Clicking another concept transitions focus correctly.
* Motion is subtle and comfortable.
* No layout jumping or visual instability occurs.
* Keyboard and screen-reader interactions are supported.
* Reduced-motion preferences are respected.
* Existing Search Engine functionality remains intact.
* The implementation works with both small and large numbers of concepts.
* The interface looks intentional, refined, and consistent with PecanRev.
* Automated tests and production builds pass.
