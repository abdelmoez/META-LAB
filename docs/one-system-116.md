# 116.md — One System: PRISMA, Screening, Extraction, PDFs, Analysis, Forest Plots, Manuscript

Implementation report for `.claude/Prompts/116.md` (v4.21.0).

Directive 116 asked for one interconnected research system rather than a set of UI
tickets, and for structural repair where the current behaviour was structurally wrong.
This report follows the Part XXIII shape: what was wrong, what changed, the data model,
cross-engine propagation, permissions, the proportion repair, performance, tests,
validation results, and what is still open.

The work landed as one commit per subsystem, each with the unit gate green before the
next began, plus adversarial-review fix commits. Every stage was reviewed by independent
agents that reproduced findings against the running engine before anything was accepted.

---

## 1. What was wrong

### 1.1 Proportion outcomes never reached Analysis (§41-51)

Not one regression but four, compounding:

1. **Raw data was not analysable.** A proportion row carrying `events`/`total` only
   became poolable after a *manual* effect-size backfill — the classic tab's
   "Calculate & Apply" or the engine's "✓ Complete". `expectedFieldsFor(PROP)` counts
   events/total, so Extraction reported the study 100% complete while Analysis said
   "No studies with an effect size yet". The two surfaces disagreed about the same row.
2. **The 107.md pooling gate blocked the normal state.** The compatibility guard treated
   *any* denominator-population or action-status mix as blocking, including the ordinary
   mid-classification state: classify one estimate and every unclassified sibling
   instantly blocked Analysis, Forest, Sensitivity and the summary table at once. 116 §49
   forbids exactly this — "do not turn a metadata safeguard into a reason that Analysis
   shows nothing".
3. **A metadata validation error dead-ended the only derivation path.** The
   "denominator description required" rule was a *blocking* error, so it could prevent
   Complete, which was the only thing that would have written the effect size.
4. **The assisted-extraction handoff filtered proportions out.** `maCompatible` knew only
   `dichotomous|continuous`, so the elements mapper dropped proportion outcomes.

### 1.2 PRISMA exclusion boxes were dead in production (§15)

`prismaFlowService` selected a column that does not exist (`ScreenDecision.reason`; the
real column is `exclusionReason`). Prisma throws a validation error, `safe()` swallowed
it, and the loader returned an empty decision array. Every project therefore rendered
"Records excluded 0" with no reasons, no matter how much screening had been done. No test
covered the loader, which is why it shipped. Separately, leader rejections
(`finalStatus='rejected'`) and resolved conflicts were never mapped into dispositions at
all.

### 1.3 PRISMA boxes could not wrap their own text (§18)

`drawBox` never wrapped: the `wrap()` helper existed but was used only for footnotes. The
automation-tools line in "Records removed before screening" is ~300px of text in a 250px
box, so it overflowed. Nothing about the box was dynamic.

### 1.4 Import provenance was dishonest (§13-14)

Parsers stamped the *file format* into the record's source field ("RIS", "BibTeX",
"EndNote", "CIW", "CSV", "TXT") and the import service mapped that into `sourceDb`, so a
record imported from a RIS file claimed to have been found in a database called "RIS". A
previous fix had removed a different, already-dead fallback and left this one live. No
parser attempted to read the *real* database (the RIS `DB` tag, EndNote's
remote-database-name), and manually imported records were filed under database searching
rather than other methods.

### 1.5 The forest plot's coordinate system (§22-25)

Four independent renderers existed. The live one built its domain from the study
estimates *excluding the no-effect value*, then silently clamped anything outside. That
single decision produced the whole reported symptom cluster: the null line pinned to a
plot edge, the "Favours" labels — anchored to that clamped position — collided with tick
labels and spilled into neighbouring columns, and the axis showed odd back-transformed
values (0.61 / 1.65 / 2.72) because ticks were generated by a fixed 0.5-stored-unit loop
rather than by the measure. Proportion plots were drawn with a no-effect line at logit 0
(50%), which invites the reader to see half the studies as "favouring" something that
does not exist for a single-arm proportion.

### 1.6 The stray `)}` (§57)

`analysisTabs.jsx` had lost the `{interp && (` opener of the plain-language interpretation
card, so its closing brace stopped being syntax and became JSX *text*, which React
printed. It was valid JSX, so only an easily-missed build warning ever mentioned it.

### 1.7 PDFs had no annotation system, and no stable identity (§71-104)

There was no annotation storage of any kind. Worse for anchoring, PDF identity was the
attachment row id, and replacing a PDF *deletes and recreates* that row — so anything
keyed to it would orphan on every re-upload. Manual uploads stored no content hash at
all, binaries served `Cache-Control: max-age=0` with no ETag, and the same file was
re-downloaded on every navigation between Screening, Conflict and Extraction.

### 1.8 Conflict resolution hid the article (§67-70)

The Conflict tab rendered a title, an author line and two decision chips. The abstract
was fetched from the server and then dropped on the floor; journal/DOI/PMID were never
selected; per-reviewer reasons, notes and ratings were not shown; reviewers were labelled
"Reviewer" with no name; and there was no PDF access at all. Reviewers were asked to
resolve a disagreement with less information than they had when they created it.

## 2. What changed, by subsystem

### 2.1 Extraction → Analysis (commit `a41530f`, r2 `b0d9b8c`)

- **Derive at the analysis boundary.** `poolableStudyView` returns a *computed view* of a
  raw proportion row with es/lo/hi derived through the exact existing `calcES('PROP')`
  logit path (same continuity correction, same rounding as the Complete-time backfill,
  pinned by a parity test). A stored effect size always wins; derived values are never
  written back, so nothing is autosaved, no provenance churns and no syncHash moves.
  `withPoolableViews` returns the *same array reference* when nothing needed deriving, so
  existing memo chains are untouched.
- Applied in lockstep across `runMeta`, `eggersTest`, `leaveOneOut`, `trimFill`,
  `influenceDiagnostics`, `checkPoolability`, `analysisTypeWarnings`, the outcome
  enumerators, and the second engine copy (`meta-analysis.js`) that the manuscript and
  server consume — so Analysis, exports and the paper cannot disagree about what pooled.
- **Two-tier compatibility gate.** Two or more real categories still block behind the
  persisted override flow. One real category mixed with unclassified rows is now a
  *warning*: pooling proceeds with a visible advisory naming the unclassified count and
  offering the filter affordances. Unclassified rows keep their own line and are never
  merged into a category.
- **Itemized eligibility reasons** (`analysisEligibility.js`) replace blank panels:
  "3 studies are missing total sample size", "1 study has events greater than total",
  "At least 2 eligible studies are required for pooling".
- **Always-visible proportion.** Both extraction surfaces show `Proportion: 0.18 (18%)`
  from events/total, alongside — never instead of — the denominator/action metadata.
- The denominator-description rule became a warning; the assisted handoff gained a
  single-arm proportion path.

### 2.2 PRISMA (commit `953ba7a`, review fixes in the r2 commit)

- The loader select was corrected and pinned by a test that parses `schema.prisma` and
  asserts every selected column exists — the specific reason the original bug was
  invisible. Leader rejections and resolved conflicts now map into dispositions.
- **Reason normalization** (`reasonFormat.js`): grouping folds whitespace and case;
  display applies conservative sentence case that upper-cases the first letter only when
  the first word is entirely lower-case, so `no MRI outcome` → `No MRI outcome` and never
  `No mri outcome`. Stored strings are never rewritten.
- **Provenance**: format tokens no longer reach `sourceDb`; genuine database detection
  was added (RIS `DB` tag, EndNote remote-database-name, nbib → PubMed) behind a
  recognized-database gate; batch-declared databases thread into record projections; and
  additive `identificationSource` / `sourceDetail` columns provide the per-record
  correction the engine already knew how to honour.
- **Inspector**: a paginated, searchable, facetted per-box record endpoint below the
  diagram, with metadata editing routed through the record-update service (validated,
  audited, undoable) while decision changes stay behind the existing finalize/revert
  domain actions. The main flow payload was slimmed to counts.
- **Layout**: every box wraps its own text with dynamic height; connectors already read
  measured geometry, so they follow. Hit targets became fractional so browser zoom cannot
  desynchronise them from the drawing.

### 2.3 Forest plots + decimals (commit `c571351`)

- One pure layout engine (`src/research-engine/charts/forestLayout.js`) now feeds both the
  live plot and the publication builder. The domain always contains the null; `place()`
  returns an explicit `clamped` flag that renderers turn into truncation arrows rather
  than silently moving a mark.
- Ticks come from the measure via the effect-type registry: log candidates for ratios,
  nice 1-2-5 steps for differences, percent candidates for proportions. **PROP gets no
  null line and no favours labels** — documented in the engine header as a deliberate
  scientific correction.
- Figure labels (title, axis label, both favours strings) persist per outcome pair and are
  edited inline; renaming an *outcome* is a separate, separately-labelled project-level
  action that migrates every name-keyed analysis map atomically.
- `analysisPrecision` reaches every Analysis page; six inline `toFixed` bypasses were
  replaced by the central formatters; p-values always floor at `P < 0.001`, including in
  the manuscript, which previously rendered `P = 0.00` for a 2-decimal project.
- §124: the journal ZIP no longer re-pools with a different model — exports reuse the
  resolved analysis, and the persisted model setting is honoured downstream.

### 2.4 Extraction field library (commit `d43f47d`)

- An 80-entry catalog across the eight standard categories, plus custom fields with ten
  data types. **35 entries alias row keys that already exist** rather than minting
  duplicates, so enabling "Country" surfaces data already extracted. Fields owned by the
  effect measure or the proportion form are deliberately not addable — a free-floating
  `events` copy would be a second source of truth for the statistics.
- Values key on stable ids (`xf_<id>`, mirroring the proven `cv_` precedent), so renaming
  a label cannot lose data. Archive, not destructive delete, is the exit for a field
  holding values.
- The new keys hash *value-conditionally*, verified against the same hardcoded pre-107
  digest that guards every stored syncHash.
- Eight downstream allow-lists now derive from the registry; the ones that stay manual are
  each pinned by a test asserting they stay out, with the reason recorded.
- The Individual Study Contributions table keeps its defaults and gains a Columns control
  reading that same registry. A column whose field is later archived is dropped from the
  render with a note, and never rewritten out of the stored selection, so un-archiving
  restores it.

### 2.5 Manuscript tables (commit `01e122c`)

- Insert → Table grid selector, caret-scoped row/column controls, plain Tab / Shift+Tab
  cell navigation that claims only the unmodified chord so the shortcut router is
  unaffected.
- Every structural operation is a pure markdown transform applied by whole-table
  replacement through the `execCommand` path — which is what keeps native undo working
  *and* fires the input event autosave depends on. Raw DOM mutation would have broken
  both silently.
- The grammar was fixed first: literal pipes round-trip instead of being corrupted to
  `/`, alignment colons survive parse → render → DOCX, and pasted Word tables pad short
  rows so columns stay aligned. Nothing the editor can produce falls outside the grammar,
  so no table can become DOM-only and vanish on the next remount.

### 2.6 Conflict tab (commit `2030ef5`)

- One shared `RecordArticleCard` renders the article header and complete abstract for both
  Title & Abstract and Conflicts (T&A output proven byte-identical and now pinned), the
  record-keyed PdfViewer mounts on the same attachment entity, and named reviewer
  decisions carry their reason, notes and rating.
- Widening the payload also closed a pre-existing leak: the legacy `reviewerDecisions` map
  is keyed by *user id*, so it disclosed colleague identity to a blinded resolver. It is
  now re-keyed to positional labels under blind mode.

### 2.7 PDF annotations (commit `d5d9511`)

- New `PdfAnnotation` relational table, dual-scoped (screening project / META·LAB
  project), keyed by **content hash** rather than attachment id.
- Rects are stored in unrotated PDF user space at scale 1 — the contract extraction
  provenance already uses. Because capture and render are the same linear function of
  scale, zoom, fit-width, sidebars, window resize and HiDPI cannot move a highlight;
  tests pin that the same physical selection captured at 0.5×, 1×, 1.25×, 2× and 3.7×
  stores byte-equal rectangles. At non-zero rotation the layer refuses to draw rather
  than guess a second projection.
- Server enforces every rule: authors edit their own, leaders/owners moderate, admins get
  nothing extra, 404 hides existence, `revision` CAS rejects stale writes, `clientId`
  makes creates idempotent, deletes are tombstones.
- Realtime is a content-free poke plus a since-delta refetch, so an incoming highlight
  never reloads the document or moves anyone's scroll.
- Undo lives in its own history scope, deliberately outside the blob scopes, so Ctrl+Z on
  a highlight can never pop a screening decision.
- PDFs now carry a hash on every upload, binaries serve ETag/304, and a session byte cache
  ends the re-download when moving between engines.

## 3. Data model and schema changes

All additive; both the SQLite dev schema and the Postgres production schema were updated,
with hand-written additive migrations under `server/prisma/postgres/migrations/`.

| Change | Table | Purpose |
|---|---|---|
| `identificationSource`, `sourceDetail` (nullable) | `ScreenRecord` | Per-record PRISMA provenance correction (§13-14) |
| `PdfAnnotation` (new) | — | Highlights, colours, comments; dual scope; content-hash keyed (§71-104) |
| `fileHash` now populated on every upload | `ScreenPdfAttachment` | Stable document identity + ETag (§73-74) |

Blob-level (project JSON, no migration needed, readers self-heal):
`project.extractionFields`, `analysisSettings.figureLabels`,
`analysisSettings.contributionColumns`, `analysisSettings.model`.

Nothing was backfilled. Legacy proportion rows keep `''` meaning "not classified", which
is a different statement from `unclear` and is displayed as such.

## 4. Cross-engine propagation

- **Screening → PRISMA**: decisions, leader rejections and resolved conflicts all reach
  dispositions; counts derive from record sets, so a count is the size of a set.
- **Import → PRISMA**: import mechanism and declared database are distinct; the diagram
  aggregates detailed sources into the correct high-level arm, and a per-record override
  exists for correction.
- **Extraction → Analysis**: raw proportion rows are analysable without a manual backfill;
  the same predicate governs the progress rail, the enumerators and `runMeta`, so those
  surfaces cannot disagree.
- **Extraction schema → Analysis**: one registry feeds both the extraction forms and the
  contributions Columns menu.
- **Analysis → Forest → Manuscript**: the plot renders the numbers Analysis computed; the
  journal ZIP no longer re-pools with a different model; decimal precision and p-value
  rules are centralized.
- **Outcome rename** rewrites `studies[].outcome` and migrates every name-keyed analysis
  map atomically.
- **PDF annotations** are addressed by content hash, so the same marks appear wherever
  that PDF is opened in the project.

## 5. Permissions

- Annotation writes are authorized server-side on every route via the canonical access
  resolvers: any member with PDF access may create; authors edit and delete their own;
  leaders/owners moderate others' and may clear all; ordinary members may clear only their
  own. Non-members get 404, not 403, so existence stays hidden. Admins receive no extra
  authority over scientific content.
- PRISMA record metadata edits require the same capability as editing records in
  screening, are validated and audited, and are blind-aware.
- Extraction schema configuration keeps the existing behaviour (members who may edit
  META·LAB content may configure fields), per §114's preserve clause; destructive
  operations confirm, and archive is preferred over deletion.

## 6. Proportion repair, explicitly (§ Part XXIII.6)

`Events` and `Total` remain the numerical inputs and are unchanged on the row. The
extraction UI shows the derived `Proportion: 0.18 (18%)` immediately. **Denominator
population** and **action status** remain metadata: they persist on the row, survive
refresh, reopen and collaboration, feed filtering/grouping and the compatibility gate —
and they never substitute for the mathematical denominator. Analysis derives es/lo/hi from
events/total at the boundary when no stored estimate exists, so entering or editing the
metadata cannot make effect data or analysability disappear. That last sentence is pinned
by an explicit regression pack (§133).

---

## 7. Performance

- **PRISMA**: the flow payload carries counts, not id arrays; box contents load through a
  paginated endpoint, so a 50,000-record project does not ship megabytes or render 50,000
  rows.
- **PDF**: annotation overlays mount only for pages inside the viewer's existing
  virtualization window; page slices keep identity so one new highlight re-renders exactly
  one page overlay; realtime carries a poke, never the document; ETag/304 plus a session
  byte cache remove the repeated downloads between engines.

## 10. Remaining limitations

Nothing here is hidden; each is a deliberate stop, not an oversight.

**Cross-engine propagation still incomplete**
1. **Outcome rename does not migrate server-side rows.** `renameOutcome` returns a
   `serverKeyMigrations` list in exactly the `outcome|||timepoint` form that
   `GradeOutcomeAssessment.outcomeKey` and `RobAssessment.outcomeId` use, but no endpoint consumes it,
   so a rename leaves GRADE and RoB rows on the old key. The remaining work is one PATCH route; note
   `GradeOutcomeAssessment` carries a unique constraint, so a merge must delete-or-keep rather than
   add one.
2. **Three surfaces still count stored effect sizes only**: `server/living/livingService.js`
   (evidence-shift alerts can never fire for a raw-proportion review), `extractionController.maReady`,
   and the classic extraction tab's own counters and row badges. Same class as §2.1; each is a
   two-line change through `poolableRow.js`, deliberately not made because `server/**` was outside the
   editing agent's scope at the time.
3. **The manuscript characteristics table does not render project extraction fields.** The dependency
   fingerprint is wired (editing a field marks sections outdated) but the rendered table is not.

**Presentations of the same numbers that do not share the new engines**
4. `InteractiveForest` (public synthesis) and the NMA mini-forest still render their own geometry;
   both consume different payload shapes. A fifth and sixth presentation of the same analysis.
5. `buildRValidationScript` deliberately pins DerSimonian–Laird so the generated R reproduces the
   app's historical headline CI. Now that the model is persisted it can disagree with the tab — worth
   an explicit decision.
6. `esMeasureName` has no AUC case, so an AUC axis reads "Effect size" (its null line is now correct).

**PDF subsystem**
7. **Focus ambiguity between two open PDF panes.** If focus-within is in one pane while the last
   pointer-down was in another, both component bindings pass their guard and the earlier registration
   wins. Damage is contained to a polite refusal (ops are document-routed), but complete arbitration
   is unbuilt. Reachable only by keyboard-navigating between two open viewers.
8. **Extra publication files** (supplements, protocols) carry no content hash on the wire, so they get
   no annotations and their bytes are not version-pinned in the session cache.
9. **`SINCE_LAG_MS` is a bound, not a proof.** A write stalled longer than the lag behind the writer
   lock still relies on the full-refresh backstops. A monotonic sequence column would be exact.
10. **No cross-store document entity.** Screening attachments and extraction study documents remain
    two stores bridged by content hash — a deliberate scope cut (D7), which is also why a cloned
    project resolves none of the original's annotations.

**Known-unclean environment**
11. The dev database holds thousands of leaked e2e projects, which is the sole cause of 15 baseline
    e2e failures. Remediation needs sign-off.

**Smaller, recorded rather than fixed**
12. `mkStudy` has drifted between its two copies (`project-model/defaults.js` carries fields
    `projectHelpers.js` lacks) — pre-existing, worth a lockstep sweep.
13. `opts.nullLine` is now a dead parameter that can still beat the registry for linear measures;
    deleting it would make "the registry is the only authority" structural rather than conventional.
14. `htmlToMd` is non-idempotent for a `<br>` inside a paragraph (converges after one further pass);
    predates this work.
15. `rowspan="0"` (obsolete HTML4 "span to end of section") degrades to a single row.
16. Below ~1280px with the navigation rail pinned the article column is improved but still tight;
    unpinning the rail resolves it. An honest floor, not a fix.
